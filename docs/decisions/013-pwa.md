# ADR-013: Progressive Web App — Installable App and Offline Playback

## Status

Accepted — **Phase 1 and Phase 2 shipped** (install UX, service worker + precache, device offline playback). See [Implementation status](#implementation-status) for gaps.

## Context

Music Library ships a web app manifest (`public/site.webmanifest`), manifest link in `root.tsx`, CSP `manifest-src 'self'`, and Media Session API integration for lock-screen controls. As of Phase 1–2 it also has a registered service worker, platform-aware install prompts, and client-side offline storage (OPFS + IndexedDB).

Server-side **Archived Audio** (Tigris via the archive worker) is not the same as **Cached Playback** on the device — do not conflate them in docs or UI copy.

The product goal is a mobile-first installed app (iOS Safari and Android Chrome equally; desktop install out of scope) that supports offline listening on the device by storing audio bytes locally (OPFS) and serving them without network.

## Decision

### 1. Two-phase rollout

**Phase 1 — Installed App:** manifest polish, manual service worker (`app/pwa/sw.ts` → `/sw.js` via esbuild), smart install prompts.

**Phase 2 — Offline Playback + Shell:** hybrid client storage, manual downloads, queue auto-cache, full cold-start offline shell. Originally planned as separate "cached playback then offline shell" phases; merged because cold start without a cached shell is too weak for an installed music app.

### 2. Install UX

Platform-aware, dismissible prompts (persist dismissal in `localStorage`); hidden when already in standalone mode:

- **Android:** capture `beforeinstallprompt`, show install button.
- **iOS:** coach mark for Share → Add to Home Screen.

**Two surfaces:** global bottom banner above the audio player, and a contextual block on the logged-in home page.

### 3. Offline scope (Phase 2)

When offline (including cold start):

| Works                                    | Blocked                      |
| ---------------------------------------- | ---------------------------- |
| Player + queue                           | YouTube sync, upload, search |
| Downloads view                           | Settings, admin              |
| `/library` (pinned downloads only)       |                              |
| User playlists list + detail (read-only) |                              |

Non-download routes show a friendly offline blocker. Playlist pages hide add/remove/reorder/sync actions.

### 4. Download model

- **Manual:** per-track download + bulk "Download playlist" (user playlists and synced YouTube playlists). No "download entire library" in v1.
- **Queue auto-cache:** cache tracks in the active queue while online for listening continuity.
- **Storage policy:** unified logical library; **pinned downloads** persist until user removes them; **queue cache** entries are LRU-evicted under pressure. A track that is both pinned and queue-cached counts as pinned.

### 5. Offline auth

**Device-trusted:** cached downloads remain playable when the session cookie has expired. Server auth gates new content and network-backed features; re-authenticate when back online.

### 6. Service worker — manual build (React Router 7)

React Router 7 framework mode (`ssr: true`) does not integrate reliably with Vite PWA plugins (`vite-plugin-pwa`, `@serwist/vite`): the build emits `index.html` after the plugin runs, breaking precache and navigation fallback ([vite-pwa#809](https://github.com/vite-pwa/vite-plugin-pwa/issues/809), [serwist#300](https://github.com/serwist/serwist/issues/300)). SPA-only mode and React Router 8 do not fix this.

**Chosen approach:** hand-written worker at `app/pwa/sw.ts`, bundled to `/sw.js` via esbuild (`build:sw` after `react-router build`; `build:sw:dev` → `public/sw.js` for local dev). Registered from `app/entry.client.tsx` via `app/utils/pwa-register.client.ts`.

**Precache (shipped):** `@serwist/build` `injectManifest` in `scripts/build-sw.ts` runs after `react-router build`, injecting the asset manifest into the esbuild-bundled `app/pwa/sw.ts` → `build/client/sw.js`. Dev uses `build:sw:dev` → `public/sw.js` with a minimal precache list. `installSerwist` in `app/pwa/sw.ts` sets `navigateFallback: '/index.html'` with a denylist for `/resources/*`, `/api/*`, and `*.data` routes. Do **not** add `@serwist/vite` or `vite-plugin-pwa` to `vite.config.ts`. Offline audio bytes live in OPFS; metadata in IndexedDB (both separate from SW cache). Do not cache presigned Tigris URLs in the SW.

**Supplemental shell cache:** `app/features/offline-app/offline-root-shell.client.ts` persists user, theme, and ENV in `localStorage` when online so root `clientLoader` can fall back on warm navigations without network. This complements (does not replace) SW precache for cold start.

### 7. Hybrid client storage — IndexedDB + OPFS

| Layer         | Contents                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| **IndexedDB** | Track/playlist metadata, cover thumbnails, pin vs queue-cache flags, playlist membership, OPFS file paths |
| **OPFS**      | MP3 bytes at `audio/{trackId}.mp3`                                                                        |

OPFS writes go through a **dedicated Web Worker** using `createSyncAccessHandle()` because Safari/iOS does not reliably support `createWritable()` on the main thread. Request `navigator.storage.persist()` where supported.

Playback reads from OPFS without loading full blobs into main-thread memory when possible. Downloads stream from presigned URL → OPFS (while online), not into the SW cache.

## Alternatives Considered

### IndexedDB-only for audio bytes

**Pros:** simpler API, main-thread writes on iOS and Android  
**Cons:** whole-blob memory for playback; weaker at scale for large offline libraries  
**Rejected:** acceptable for v1 but weaker long-term; hybrid chosen upfront.

### OPFS-only

**Pros:** clean file storage  
**Cons:** no query layer for Downloads/library/playlist offline views  
**Rejected:** metadata store still required.

### Separate offline shell phase after playback

**Pros:** smaller initial Phase 2 scope  
**Cons:** cold start offline fails until shell ships  
**Rejected:** merged into Phase 2.

### Strict session for offline playback

**Pros:** simpler auth model  
**Cons:** expired session on a flight locks user out of their downloads  
**Rejected** in favor of device-trusted cached playback.

### `vite-plugin-pwa` in `vite.config.ts`

**Pros:** zero-config precache, manifest injection, dev SW  
**Cons:** RR7 build order excludes `index.html` from precache; `generateSW` navigation fallback throws at runtime  
**Rejected:** incompatible with RR7 framework mode; issue open since Dec 2024.

### `@serwist/vite` in `vite.config.ts`

**Pros:** modern Workbox fork, same DX as vite-plugin-pwa  
**Cons:** fork inherits the same build-timing bug; prod builds skip SW when `build.ssr === true` for all RR7 environments  
**Rejected** as a Vite plugin; precache ships via `@serwist/build` `injectManifest` post-build in `scripts/build-sw.ts`.

### React Router 8 upgrade

**Pros:** new Vite Environment API build pipeline  
**Cons:** large migration (Vite 7+, breaking flags); no documented fix for PWA plugin integration  
**Rejected** as a PWA unblocker; revisit only if upgrading for other reasons.

### SPA-only mode (`ssr: false`)

**Pros:** simpler offline shell mental model  
**Cons:** does not fix PWA plugin build order (repro uses SPA mode); requires rewriting 55+ server loaders, auth, CSP nonces, and Epic Stack patterns  
**Rejected:** high cost, no PWA benefit; stay on SSR.

### Known gaps (not blocking v1)

- OPFS streaming playback without loading full file into memory
- Bulk "download visible library" action
- Cover re-download for tracks downloaded before cover-cache shipped
- Cold-start offline without SW precache in dev (production build required for full shell)

## Consequences

- A service worker is required even for "install only" — Chrome install criteria demand it.
- `app/features/offline-storage/` owns device bytes and metadata; the audio player checks local storage before `/resources/audio/:trackId` when offline.
- The unified `offlineClientMiddleware` substitutes offline stub data on supported routes when network is unavailable (no per-route `clientLoader`).
- iOS real-device testing is mandatory for OPFS write path, installed-PWA storage quotas, and Web Share download fallback.
- Glossary and settled decisions live in `docs/CONTEXT.md` (PWA section, decisions #43–#58).
